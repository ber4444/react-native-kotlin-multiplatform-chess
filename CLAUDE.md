# React Native + Kotlin Multiplatform Chess

## Architecture & Project Structure

- **Monorepo Structure**:
  - `my-app/`: React Native application using Expo SDK 56, React Native 0.85, and Fabric / New Architecture.
    - Native 3D rendering uses **React Native Filament** (Metal on iOS, Vulkan/OpenGL on Android).
    - Web / Desktop 3D rendering uses **three.js** (WebGL).
    - TypeScript typed gateways in `src/chess-core/` and `src/on-device-ai/` consume generated Kotlin/JS bundles.
  - `chess-core/`: Thin Kotlin/JS (IR) wrapper around the published Maven artifact `io.github.ber4444:chess-core`.
    - Exposes `@JsExport` facade (`ChessSession.kt`, `JsChessEngineAdapter.kt`).
    - Generates TypeScript definitions (`chess-core.d.ts`) via Gradle `copyJsToApp`.
  - `on-device-ai/`: Kotlin/JS consumer and wrapper for `io.github.ber4444:ondeviceai` and `io.github.ber4444:coachapi`.
    - Exposes `@JsExport` facade (`OnDeviceAiSession.kt`) and generates definitions via Gradle `copyJsToApp`.

## Continuous Native Generation (CNG) & Native Code

- **Never edit or commit `my-app/android/` or `my-app/ios/` directly**. Both directories are generated by `npx expo prebuild` and are gitignored.
- **Native Configuration**:
  - Store native configs (permissions, build properties, splash, app icons) in `my-app/app.json`.
  - Advanced build customizations belong in config plugins under `my-app/plugins/` (e.g., `my-app/plugins/withGradleHeap.js` configures 4 GB Gradle heap for packaging large Stockfish binaries).
- **Native Code / Modules**:
  - Write custom native code as local Expo modules under `my-app/modules/` (e.g., `my-app/modules/stockfish/`) using the Expo Modules API. Local modules are autolinked.
- **Regenerating Native Projects**:
  - Run `npx expo prebuild --clean` in `my-app/` after modifying `app.json`, config plugins, or native modules.
- **Development Builds**:
  - Uses `expo-dev-client`.
  - Run `npm run android` or `npm run ios` in `my-app/` to build dev client binaries. Once installed, `npm start` serves JS bundles without rebuilding native code unless native changes occurred.

## Common Commands & Workflows

Run from `my-app/`:
```bash
npm install                     # Install dependencies
npm run build:core              # Compile chess-core & on-device-ai Kotlin/JS into src/generated/
npm run prepare:assets          # Split chess.glb + convert piece SVGs
npm run typecheck               # Run TypeScript check (tsc --noEmit)
npm run lint                    # Run ESLint (expo lint)
npm run web                     # Start Expo web development server
npm run desktop                 # Run Electron desktop app
npm run android                 # Build and run Android development build
npm run ios                     # Build and run iOS development build
```

Run Kotlin unit tests:
```bash
cd chess-core && ./gradlew jsNodeTest      # chess-core Kotlin/JS tests
cd on-device-ai && ./gradlew jsNodeTest    # on-device-ai Kotlin/JS tests
```

> **Note on GitHub Packages**: Building `chess-core` and `on-device-ai` requires a GitHub PAT with `read:packages` permission (`CHESS_PACKAGES_TOKEN` or `GITHUB_PACKAGES_TOKEN` / `gpr.key`).

## Dependency & Security Management

- When adding or upgrading npm dependencies in `my-app`, ensure compatibility with Expo SDK 56 and React Native 0.85.
- For Kotlin/JS lockfiles (`kotlin-js-store/yarn.lock`), update via Gradle (`./gradlew kotlinUpgradeYarnLock`) or declare Yarn resolutions in `build.gradle.kts`.
